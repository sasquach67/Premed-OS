# T1 — Academics Daily gap closure and handoff 57

**Stage:** F — audit and promotion evidence only; narrowly scoped fixes may be made only for an observed Daily failure  
**Build authority:** `BUILD-MANIFEST.md` Daily rows = YES  
**Visual authority:** approved Variant A Daily/Class Hub mockups, exact shared visual recipes  
**Behavior authority:** `tabs/01-academics.md` plus settled lecture-first, syllabus-led, Materials-versus-Guide and class-assignment decisions

## 1. Single objective

Prove the current Daily/Class Center/Class Hub implementation across local-first
behavior, migration, persistence, controls, build, and real desktop/tablet
light/dark rendering. Correct only a concrete failure visible in that proof. If
the browser surface is unavailable, do not infer visual success from CSS;
produce an exact continuation handoff naming the routes, states, viewport,
theme and comparison source still required.

## 2. In scope

- Daily Class Center cards, add-class/type selection, cold start and recovery.
- Class Hub Overview lecture journal/capture, Materials, syllabus-led Topics,
  course Assignments and Guide/Course lens.
- Global Assignments, syllabus import, Review Session and Daily-owned error,
  empty and reload states.
- Guide proposal creation from confirmed syllabus or saved lecture evidence;
  edit, accept, dismiss, source attribution, migration and class scoping.
- Course lens application only when its evidence is in the selected material.
- Focused/full tests, TypeScript, production build and inert-control audit.
- A Claude-ready continuation report under `implementation/`.

## 3. Excluded

- Planning surfaces and data behavior.
- Flashcards and generated-output work outside an existing Daily handoff.
- Mockup HTML/Markdown, Variant Lab registry, promotion status and shared visual
  tokens.
- Canvas or another external integration, new product semantics, mobile visual
  proof, and any source fabrication.

## 4. Acceptance

1. Current v37 migration is pure, idempotent and lossless for legacy lecture
   proposals; first-use arrays are honest and reload retains proposal lifecycle.
2. Syllabus suggestions require a retained local syllabus and confirmed quoted
   passage. Lecture suggestions require the exact saved finding/chunk/lecture.
3. Edit/accept/dismiss is live, class-scoped, and accepted notes retain exact
   source references. Invalid or partial evidence cannot be accepted.
4. Course lens is optional, course-scoped, reviewable, and cannot enter a study
   guide unless every cited evidence chunk is in that request's selected set.
5. Transcript remains first, supporting evidence optional and secondary, and
   study work reads only selected attached sources.
6. Full tests, TypeScript and production build pass. Every visible Daily control
   has a real handler, native form behavior, route, trigger child, or honest
   disabled state.
7. Desktop and tablet, light and dark screenshots are captured from the running
   app and compared to the approved mockups. If no browser is available, this
   criterion is BLOCKED and the exact continuation script is written; it is not
   marked passed from static inspection.
8. No surface is marked BUILT and no unrelated dirty file is staged.

## 5. Router and stop rule

- A test, migration, persistence or control failure routes to the smallest
  backend/component hunk that fixes that exact failure, followed by the entire
  audit again.
- A literal measured visual mismatch routes to the owning Daily component or
  its already scoped stylesheet, copying exact mockup values.
- Browser unavailability, external provider configuration, or a new product
  decision is a genuine stop. Record it for Claude with exact evidence and do
  not substitute source inspection for the missing proof.

## 6. Required handoff

The report must include exact inspected routes/states, proof commands and
counts, affected files, known passing behavior, remaining visual/external
gaps, and a conflict-safe commit or primary-targeted patch. It must distinguish
current proof from earlier screenshots and must not claim promotion readiness
without all six build proofs.
